# Painel Ping v1.9.1

Correção urgente: os dados deixam de depender da pasta da release.

- Cadastro, mapa salvo e histórico usam uma pasta fixa do usuário. No Windows: `%LOCALAPPDATA%\PainelPing\data`.
- A primeira execução procura os dados de versões anteriores no projeto e nas pastas de versões próximas. Arquivos são validados e copiados antes de ativar a migração.
- Os arquivos antigos permanecem intactos; backup adicional em `data/backups/before-migration`.
- Origens diferentes interrompem a inicialização com instruções para escolher `LEGACY_DATA_DIR`; nenhum conjunto é misturado ou sobrescrito.
- Dados existentes na pasta fixa sempre têm prioridade. Próximas atualizações reutilizam os mesmos arquivos.
- `DATA_DIR` permite um caminho absoluto personalizado para instalações de servidor/serviço.
- Uma trava impede duas instâncias de escreverem simultaneamente nos mesmos dados.

## Primeira atualização

1. Pare a versão antiga com Ctrl + C e mantenha sua pasta.
2. Extraia esta release perto da versão antiga, instale com `npm install` e inicie com `npm run dev`.
3. Confira no terminal o caminho persistente e a mensagem de migração.
4. Se o terminal listar várias origens, ou se sua versão antiga estiver em outro local, defina `LEGACY_DATA_DIR` no `.env` apontando para a pasta antiga `backend/storage` e reinicie.

Após migrar, as próximas releases não exigem copiar os dados. Preserve a pasta fixa e mantenha backups. Preferências do navegador continuam locais. Só mapas salvos podem ser migrados; arquivos apagados exigem backup para recuperação.

## Validação

169 testes automatizados, incluindo migração, preservação dos dados/originais/backups, atualização entre releases, origens conflitantes, arquivos inválidos e trava de instância. Cadastro e mapa também conferidos pela API após iniciar o backend em duas pastas diferentes de release.
